# Jev용 별도 파서

2026-09-28 작성. 사용 중인 `scripts/parse_bcp_evidence.py`를 수정하거나 가져다 쓰지 않는 **독립 실행 파일**이다. 저장된 수집본을 읽어서 Jev가 읽을 텍스트와 질문 초안을 만든다. API 호출이나 최종 Y/N 판정은 하지 않는다.

## 어디부터 보면 되는가

[최신 추출 요약](results_jev/20260928T060234KST/20260927T224906827801Z/Jev_파서_요약.md)을 연 뒤 각 리테일러의 `본문_검토.md`를 확인한다. 예를 들어 [Coolblue 본문 검토](results_jev/20260928T060234KST/20260927T224906827801Z/coolblue/본문_검토.md)에서는 냉장고 보관·에너지 절약·DoorCooling 설명이 제목과 함께 추출됐는지 볼 수 있다. 이 중 다섯 영역의 Jev 시험 결과는 아래에 별도로 있다.

첫 검증은 저장된 LG 냉장고 BCP 9개를 사용했다. 입력 묶음 `results/20260928T060234KST`에는 9월 26일 수집본 6개와 9월 28일 재수집본 3개가 함께 들어 있다. 이번 작업에서 재크롤링하지 않았다.

## 실행

프로젝트 루트에서 실행한다. `--brand`, `--category`는 입력 묶음 전체에 적용되므로, 서로 다른 브랜드·제품군을 섞은 묶음에는 동일한 값을 지정하지 않는다. 지정하지 않으면 미입력 상태로 남는다.

```bash
python3 '1차 테스트/bcp-zyte-poc/scripts/parse_bcp_for_jev.py' \
  '1차 테스트/bcp-zyte-poc/results/20260928T060234KST' \
  --brand LG --category refrigerators
```

표준 Python 라이브러리만 사용한다. 키나 외부 서비스 연결이 필요 없다. 입력은 각 리테일러의 `pages/<리테일러>/brand-category/`에 있는 `raw.html`, `capture-state.json`, `response.json`이다. 일반 Brand Page는 이 실행기의 처리 대상이 아니다.

결과는 매번 `results_jev/<입력 묶음 이름>/<UTC 실행 시각>/`이라는 **새 폴더**에 저장한다. 실행 시각 끝의 `Z`는 한국 시간보다 9시간 느린 UTC 표시다. 입력 폴더, 기존 `parsed`, `assessed`, `manifest.json`과 기존 파서는 수정하지 않는다. 개발 중 생성한 앞선 실행 폴더도 보존하며, 위 링크는 최종 코드로 다시 실행한 결과다.

## 본문을 묶는 방법

특정 영어 단어가 있는 문장만 찾지 않고 HTML 구조와 길이를 기준으로 나눈다. 영역마다 제목·문장·이미지 alt·링크와 원본 위치를 묶는다. 기본적으로 문장 5,000자 이하, 제목 3개 이하, 이미지 12개 이하, 링크 24개 이하가 되도록 하위 요소로 나눈다. 긴 텍스트 하나는 여러 조각으로 보존하며 조각 여부와 시작 위치를 기록한다. 이 숫자는 파서의 작업 단위이며 진단 기준이 아니다.

스크립트·스타일·HTML 메타 영역과 명시적인 공통 머리말·꼬리말·탐색 메뉴를 제외한다. 본문 안의 메뉴는 보존한다. 단순 `div`로 구현된 공통 메뉴·상품 필터는 남을 수 있으므로 추출 결과 전체가 진단 대상 본문이라고 단정하지 않는다. `hidden`, `aria-hidden`, 인라인 숨김 스타일은 별도 영역으로 보존하고 Jev 요청 초안에서 제외한다. 외부 CSS에 따른 숨김 여부와 아코디언을 열 수 있는지는 이 코드가 검사하지 않는다.

`source_path`, `source_line`은 저장된 HTML에서 찾을 위치다. 원본이 한 줄로 저장됐을 수 있으므로 제목 순서는 행 번호 대신 HTML 요소 등장 순서로 연결한다. 이 순서가 화면 위치를 뜻하지는 않는다.

초안 질문은 [사용자 수정 기준표](../BCP_9개_항목_판정기준_검토표.md)의 단순 소개 제외, 애매한 USP 불인정, 질문답변 한 쌍 인정 등을 반영했다. ID20의 `evidence_missing`은 추출 내용·맥락이 빠진 경우다. 온전한 내용을 보아도 USP인지 애매한 경우는 `does_not_match`로 묻는다. Coolblue 다섯 영역에서는 AI 검토 메모와 Jev 결과를 비교했으나 사람 정답표에 대한 정확도는 검증하지 않았다.

## Jev 요청 초안의 한계

요청 모양은 [Jev Choice 공식 문서](https://docs.typesafe.ai/primitives/choice)의 `model`, `state`, `questions`, `type=choice`, `criteria`를 따른다. `jev-1.13.0`을 명시한다. [모델 문서](https://docs.typesafe.ai/models)에 따르면 텍스트·JSON을 입력으로 사용하며 이미지 자체를 읽지 않는다. 원문은 번역하지 않았으므로 다국어 정확도를 검수해야 한다.

선택지는 `matches`(내용 조건에 맞음), `does_not_match`(맞지 않음), `evidence_missing`(필요한 내용·맥락 누락)이다. **영역별 의미 분류**이며 페이지 전체 Y/N과 다르다. 화면 표시·배너 위치·링크 작동을 추측하지 말도록 질문에 명시했다. 웹페이지 문장은 판단 자료로 취급하고 그 안의 지시를 따르지 않도록 했다.

한 요청이 UTF-8 JSON 24,000바이트를 넘으면 `oversize_needs_split`으로 표시한다. 이는 임시 크기 점검이며 공급자의 토큰 제한을 정확하게 계산한 것은 아니다. 실제 호출기는 아직 없고 모든 초안은 미전송이다.

이번 9개 페이지에서 추출 영역은 3,571개, 요청 초안은 2,412개다. Datart의 필터·상품 목록 등 때문에 요청이 많이 생겼다. **그대로 전체 전송하기에 적합하다고 검증된 묶음은 아니다.** 먼저 한 페이지의 추출 영역과 질문을 검토하고, 불필요한 영역 선별·묶음 구성·호출량을 조정해야 한다. 단어가 없다는 이유로 후보를 누락시키거나 후보 0개를 N으로 바꾸지 않는다.

수집 성공 여부·잔류 쿠키·필수 영역·필수 하단 도달 여부에 문제가 있으면 요청 초안을 만들지 않는다. 검사 문제 0건은 모든 내용의 추출 완전성을 보증하지 않는다. 숨김 문구·CSS·iframe·shadow DOM·이미지 속 글자·위치 등의 한계가 있으므로 `absence_verdict_allowed=false`로 보존한다.

## Coolblue 5개 영역 Jev 시험

[선별 검토 메모](results_jev/coolblue_trial/20260927T213640809482Z/선별_검토.md)에 구체적인 비교 사례를 정리했다. [시험 준비 결과](results_jev/coolblue_trial/20260927T213640809482Z/검토_결과.md)는 5개 영역의 원문과 질문을 담고 있으며, 현재 API 미호출 상태다. 네덜란드어 원문은 Jev에 그대로 전달한다. TypeSafe의 [공식 API 문서](https://docs.typesafe.ai/api)에 명시된 `POST /v1/systemone`, Bearer 인증, Choice 답변 구조를 따르는 [5건 한정 실행 파일](scripts/run_jev_coolblue_trial.py)을 추가했다. 한 페이지의 모든 17개 초안이나 9개 리테일러의 2,412개 초안을 자동으로 보내지 않는다.

키가 있는 환경에서 프로젝트 루트 `.env`에 `TYPESAFE_API_KEY=...`를 넣거나 환경변수로 지정한 뒤 다음을 실행하면 **5건의 실제 API 요청**을 보낸다. 키 자체는 저장하거나 화면에 출력하지 않는다. `--live`를 빼면 요청을 준비만 한다.

```bash
python3 '1차 테스트/bcp-zyte-poc/scripts/run_jev_coolblue_trial.py' \
  '1차 테스트/bcp-zyte-poc/results_jev/20260928T060234KST/20260927T224906827801Z/coolblue' \
  --live
```

매 실행 결과는 새 `results_jev/coolblue_trial/<UTC 시각>/`에 저장한다. `review.json`과 `검토_결과.md`에서 영역별 Jev 선택값을 읽고, `responses.jsonl`에서 모델 이름·각 선택지 확률·confidence·사용 토큰을 확인한다. Choice의 confidence는 **확률 분포의 모양**을 나타내며 사람 기준 정답률이 아니다. 결과를 먼저 위 선별 검토 메모와 대조한다. 실제 호출을 해도 이것만으로 페이지의 최종 Y/N이 만들어지지 않는다.


### 2026-09-28 실제 Jev 소량 시험 결과

프로젝트 루트 `.env`에 키가 설정된 뒤 Coolblue의 선별 영역 5개를 두 번 호출했다. 첫 질문에서 개별 상품 카드를 Why LG로, 리테일러 배송 안내를 제품 USP로 잘못 분류했다. 질문에 각 제외 조건을 명시한 2차에서는 두 사례가 비해당으로 바뀌었다. FAQ 경계 사례의 낮은 확신도와 전체 페이지 판정의 미완료 상태까지 [실제 응답 비교](results_jev/coolblue_trial/20260927T224914051369Z/Jev_1차_2차_비교.md)에 기록했다. 키는 결과 파일에 저장하지 않았다. 현재 `parse_bcp_for_jev.py`는 질문을 구체화한 **v2**이며 [v2 전체 초안](results_jev/20260928T060234KST/20260927T224906827801Z/Jev_파서_요약.md)이 새 폴더에 있다. 2,412개 전체를 호출하지 않았다. **해석 정정:** ID20만을 위해 후보군을 별도로 찾은 것은 아니다. 일반 본문 영역에서 AI가 이미 제외되어야 한다고 생각한 배송·설치 사례를 골라 질문을 수정하고 같은 사례에 다시 적용했다. 이 시험은 API 연결과 질문 문구의 영향을 보여 주지만 Jev 판정 정확도를 검증하지 않는다.
