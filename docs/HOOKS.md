# 프로젝트 결정 메모리 훅

이 훅은 대화 중 확정된 프로젝트 의사결정이 나왔을 때 기준 문서 갱신을 놓치지 않도록 돕는다. 예시는 “크롤링 공급자로 Zyte를 쓰기로 했다” 같은 문장이다.

## 작동 방식

```text
사용자 프롬프트
  → UserPromptSubmit: 확정 결정 후보 탐지
  → AI: 실제 확정 여부와 영향 문서 판단
  → DECISIONS.md 및 관련 기준 문서 갱신
  → Stop: DECISIONS.md 갱신 여부 확인
      ├─ 갱신됨: 정상 종료
      └─ 미갱신: 한 번 더 작업을 이어가도록 요청
```

훅이 문서 내용을 직접 생성하지는 않는다. 정규식만으로 “결정했다”와 “결정할까”의 모든 문맥을 정확히 구분할 수 없기 때문이다. 훅은 후보를 표시하고 누락을 검사하며, AI가 사용자 문맥을 읽어 확정 여부와 파급 범위를 판단한다.

## 구성 파일

- `.codex/hooks.json`: `UserPromptSubmit`과 `Stop` 이벤트를 연결한다.
- `.codex/hooks/project_decision_memory.py`: 후보 탐지, 턴별 임시 상태, 종료 검사를 수행한다.
- 임시 상태는 운영체제 임시 폴더의 `codex-project-decision-hooks/`에 저장한다. 프로젝트 지식은 이 상태 파일에 의존하지 않고 Markdown에 남긴다.

프로젝트가 현재 경로에서 이동하면 `.codex/hooks.json`의 스크립트 절대 경로를 새 경로로 바꾼다. 2026-10-22 현재 Git 저장소지만 훅 설정은 여전히 절대 경로를 사용한다. Git 루트를 이용하도록 바꾸는 것은 별도 구현 후보이며 이번에 훅 코드를 변경하지 않았다.

## 활성화

프로젝트 로컬 훅은 신뢰된 `.codex/` 구성에서만 실행된다. 새 세션을 이 프로젝트 루트에서 시작한 뒤 Codex의 `/hooks`에서 두 훅의 정의와 스크립트를 검토하고 신뢰한다. 훅 파일이 바뀌면 해시가 바뀌므로 다시 검토해야 한다.

문서 작성 당시 로컬 CLI의 기능 목록에서 `hooks`가 stable/true로 관찰됐다는 기록이다. 2026-10-22 점검에서는 현재 앱·CLI의 설정이나 실제 훅 실행 여부를 새로 검증하지 않았다.

## 결정으로 기록할 것

- 기술·외부 서비스·데이터 소스의 채택 또는 폐기
- 지표 정의, 분모, 집계, 예외 처리의 확정
- 지원 국가·리테일러·제품군·사용자 범위의 확정
- 배포·인프라·보안·운영 책임과 관련한 확정
- 기존 문서의 미결 사항을 닫는 사용자 판단

아이디어, 비교 요청, 후보 검토, 아직 답하지 않은 질문은 결정으로 기록하지 않는다. 사용자가 이전 결정을 번복하면 기존 행을 조용히 덮어쓰지 말고 새 결정을 추가해 대체 관계를 남긴다.

## 문서 반영 규칙

확정 결정은 항상 `docs/DECISIONS.md`에 날짜·결정·근거를 기록한다. 그 뒤 실제 영향을 받는 문서만 고친다.

| 영향 | 함께 갱신할 문서 |
| --- | --- |
| 목적·범위·아키텍처·현재 상태 | `PROJECT_CONTEXT.md` |
| 지표·계산·데이터 판정 | `docs/BUSINESS_RULES.md` |
| AI가 매 작업에서 지켜야 할 규칙 | `AGENTS.md` |
| 새 원본 또는 출처 | `docs/SOURCES.md` 및 필요 시 추출본 |

확정 여부가 아닌 경우에는 훅이 모델에게 제시한 `resolve --ignore` 명령을 실행해 해당 턴의 후보를 해제한다. 이 해제는 프로젝트 결정 기록에 들어가지 않는다.

## 저장소를 넘나드는 작업의 한계

2026-10-22 코드 확인: 이 훅은 사용자 프롬프트의 결정 표현을 정규식으로 찾고, `Stop`에서 이 저장소 `docs/DECISIONS.md`의 수정 시각이 바뀌었는지 검사한다. 문서 내용의 정확성·완전성이나 관련 기준 문서의 실제 갱신까지 검증하지 않는다. 다른 저장소의 커밋·별도 채팅의 결정·운영 배포도 수집하지 않는다. 훅 설정 파일의 존재만으로 현재 세션에서 실행됐다고 보증하지 않는다.

따라서 다른 LG 저장소의 작업을 다룰 때는 [연결 저장소 동기화 점검](REPOSITORY_SYNC.md)의 절차로 이 저장소에 영향을 주는 변경을 명시적으로 반영해야 한다. 이번 점검은 문서 보완이며 자동 감시·예약 실행이나 다른 저장소용 훅 설치를 포함하지 않는다.

## 검사 방법

후보 탐지기의 기본 사례는 다음 명령으로 확인한다.

```bash
/usr/bin/python3 .codex/hooks/project_decision_memory.py self-test
```

훅은 명시적 결정 표현을 놓치지 않게 하는 보조 장치다. 완전한 정책 집행 경계가 아니며, 표현이 간접적이면 탐지하지 못할 수 있다. 그래서 `AGENTS.md`에도 같은 문서 유지 규칙을 둔다.
