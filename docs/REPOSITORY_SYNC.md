# 연결 저장소 작업과 연구 문서의 동기화 점검

점검일: 2026-10-22, 한국 시간. 이 저장소는 사용자가 LG 프로젝트를 연구·이해하고 시험하는 공간이다. 다른 저장소의 모든 커밋을 복제하지 않고, 목적·데이터 출처·계산 기준·운영 상태에 영향을 주는 변경과 근거를 연결한다.

## 점검 결과

**기존 문서만으로는 다른 저장소의 최근 작업을 충분히 따라갈 수 없었다.** 회의 자료와 이 저장소 안의 시험 이력은 비교적 잘 보존됐지만, 시스템 설명은 10월 12일 확인에 머물렀고 10월 19~22일의 8월 보고·관리자·HTML 보고서·판정 기준 변경이 빠져 있었다. 이번에 마스터 문서·규칙·자료 목록을 연결하고 과거 설명의 적용 시점을 표시했다.

관련 저장소의 `knowledge/`에는 후속 내용이 상당수 기록돼 있다. 다만 그곳도 현재 구현과 과거 설명이 섞여 있어 문서 이름이나 ‘최신’ 표기만으로 정본을 판단할 수 없다. 아래는 **로컬 코드 확인**, **다른 저장소 문서에 남은 검증 기록**, **과거 대화 기록**, **미확인**을 구분한 결과다. 이번 점검에서 운영 사이트·DB를 새로 조회하거나 재채점·배포하지 않았다.

## 대화에는 있으나 연결이 약했던 연구 내용

- **URL 모수의 용도 구분:** 대화 「하은님 메일을 시작으로 url 모수 알아보기」(아래 식별자)에는 10월 12일 메일을 바탕으로 대시보드용·개선 점검용·글로벌 진단용 목록, 검수 표본, 검색 시작 링크를 구분한 해석이 있다. 이 구분은 유용한 연구 메모지만 실제 목록이 서로 다르거나 국가가 겹치지 않는다는 증거는 아니다. [메일 원문 위치](https://codestep.dooray.com/mail/systems/inbox/4441796828355238548)는 남기되 이번에 메일을 재열람하지 않았으므로 과거 대화의 분석으로만 기록한다.
- **PDP 후보 선별 작업:** 대화 「PDP 모수 수집 단계 파악」은 검색 결과→브랜드 선별→제외·중복 검토→대상 확정이라는 회의 설명을 정리했다. [10월 13일 회의 정리의 ‘수집 대상과 예외 처리’](../meeting-notes/2026-10-13/회의_정리.md)와 파이프라인 선언문 ‘PDP URL 모수 확정’(LGOP-053)을 함께 읽어야 한다. 후자는 현재 모수 단계가 리퍼·재판매·부품 제외나 주소 정규화를 하지 않는다고 설명한다. 앞 단계의 전달 목록에서 이미 했는지는 별도 확인 대상이다.

대화 찾기용 식별자: 「하은님 메일을 시작으로 url 모수 알아보기」 `01a132d2-aeca-7282-a6d0-56bcccc6db3f`, 「PDP 모수 수집 단계 파악」 `01a13eb8-2e75-72d1-b045-0dd68734450d`, 「1차 보고 대시보드 지표 교체」 `01a1520c-9ad0-7901-b494-87c25fa22b94`, 「대시보드 DB와 8월 버전 확인」 `01a152b0-f443-7c32-a075-9481d1acabc0`. 이번 점검에서 이 대화들의 최근 턴을 읽었다. 대화 기록을 원본 메일이나 코드 검증의 대체 근거로 사용하지 않는다.

1. 다른 저장소의 작업 내용을 반영할 때 저장소·브랜치·확인 커밋을 남긴다.
2. 목적·구성·공개 범위는 `PROJECT_CONTEXT.md`, 계산·분모·판정은 `BUSINESS_RULES.md`, 사용자가 확정한 변경은 `DECISIONS.md`, 원본과 후속 자료 위치는 `SOURCES.md`에 기록한다.
3. 해당 저장소의 단어집·선언문·구체적 코드·검증 기록으로 연결하고 전체 내용을 중복 복사하지 않는다. 현재 기준이 바뀌어도 과거 시험·회의 원문은 보존한다.
4. 문서의 미구현 목록을 새 구현 지시로 취급하지 않는다. 구조 점검만으로 유료 수집·모델 호출·DB 쓰기·배포를 시작하지 않는다.

현재 [결정 메모리 훅](HOOKS.md)은 이 저장소 사용자 발언의 결정 표현과 문서 갱신 시각을 확인하는 보조 장치다. 다른 저장소의 커밋이나 다른 채팅의 결정을 자동으로 가져오지 않는다. 따라서 현재 구조에서는 저장소를 넘나든 작업 뒤에 명시적으로 문서를 반영해야 한다.

## 이번 문서 변경의 검증

추가·변경한 로컬 링크 대상 92개와 문서 제목 연결 14개를 검사해 누락이 없었고, `git diff --check`를 통과했다. S13 원본 파일의 존재·크기·해시도 재확인했다. 문서만 변경했으므로 애플리케이션 테스트·운영 조회·보고서 생성은 실행하지 않았다. 연결 저장소의 파일은 수정하지 않았다.
