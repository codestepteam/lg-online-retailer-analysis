# Brand Category Page 수집·판정 검증 안내

작성일: 2026-09-23, 최종 갱신: 2026-09-28. D010으로 BCP의 9개 항목을 수집·판정하는 범위가 정해졌고, 2026-09-25 D012에서 **1차 테스트 입력에 일반 Brand Page도 포함하되 ID8·9·10만 수집**하도록 구체화됐다. Brand Category Page는 9개 항목을 모두 수집하고 ID18~23은 일반 Brand Page에서 제외한다. 이 문서의 실행 순서·첫 샘플·자동화 방식은 별도 확정이 없는 부분에 한해 AI 제안이다.

## 2026-09-26 9개 대표 페이지 수집 액션 구현

사용자가 직접 확인한 쿠키 창·사람 확인 화면과 Obsidian Vault의 `리테일러 특징` 메모를 반영해 9개 리테일러의 `brand-category` 설정을 갱신했다. 모든 대표 페이지를 밑까지 내리고, 사이트 안에서 펼쳐지는 설명·제품 더보기·질문은 필요한 경우에만 누른다. 2페이지로 이동하는 Alza·Datart 링크와 Coolblue의 별도 도움말 페이지는 현재 Brand Category Page 증거를 보존하기 위해 누르지 않는다.

사람 확인 화면은 자동으로 누르지 않는다. MediaWorld·MediaMarkt Netherlands·MediaMarkt Spain에서 관찰한 안내 문구가 수집 결과에 남으면 항목을 N으로 판정하지 않고 수집 실패로 기록한다. 정상 수집 후에는 ID8·9·10의 기초 판정에 필요한 이미지 설명·크기, 페이지 제목·설명·최상위 제목·검색엔진 설정, 대표 주소 표시를 별도 데이터로 남긴다. ID22·23의 후보 파악을 위해 클릭 가능한 버튼·링크의 문구와 목적지도 남긴다.

설정·대표 URL·항목별 수집 근거와 추가 판단이 필요한 부분은 [`1차 테스트/Zyte_BCP_9개_항목_수집_액션_정의.md`](../1%EC%B0%A8%20%ED%85%8C%EC%8A%A4%ED%8A%B8/Zyte_BCP_9%EA%B0%9C_%ED%95%AD%EB%AA%A9_%EC%88%98%EC%A7%91_%EC%95%A1%EC%85%98_%EC%A0%95%EC%9D%98.md)에 정리했다. 70개 전체 대표 요청 재생성·정적 검사·9개 BCP 요청 실행 전 검사를 통과했고, 2026-09-26에 9개 대표 페이지 실수집을 완료했다. 9개 모두 본문 수집 완료 조건을 통과했다. 전체 화면 이미지는 5개만 완전하고 4개는 Zyte의 10,000픽셀 제한으로 잘렸지만, D016에 따라 이는 파서 작업을 막는 수집 실패가 아니며 전체 화면 이미지는 보조자료로 사용한다. 결과와 완전성 점검은 [`results/20260926T120245KST/`](../1%EC%B0%A8%20%ED%85%8C%EC%8A%A4%ED%8A%B8/bcp-zyte-poc/results/20260926T120245KST/)에 보존했다. 항목 판정은 아직 실행하지 않았다.

## 2026-09-25 실제 페이지 확인과 설명 보완

- **BCP는 Brand Category Page의 약자**로, 리테일러 안에서 특정 브랜드의 특정 제품군을 소개하고 제품 탐색으로 이어주는 페이지를 뜻한다. 예: Coolblue의 LG 냉장고 페이지. **CTA는 Call To Action의 약자**로, 여기서는 “LG 냉장고 전체 보기” 또는 제품 상세로 이동하는 클릭 가능한 버튼·링크를 뜻한다.
- `BCP!B4`라는 표기는 **『EY_LGE HS 온라인 리테일 클리닉 진단 항목_v1.95_20260915 (1).xlsx』의 BCP 탭에서 B열 4행에 있는 안내 문구**를 가리킨다. 이 문구에 쓰인 Controlability는 정확한 업무 정의가 확인되지 않았다. 콘텐츠 수정 가능성을 뜻할 수 있다는 것은 해석이며 확정 정의가 아니다.
- 같은 엑셀의 **BCP 탭 → Brand Category Page URL 열**에서 대상 후보를 볼 수 있다. 이전 답변의 “기존 결과 파일”은 **『★EY_LGE_Clinic_Assessment Summary_Improvement Tracker_V0.1_20260911 (1).xlsx』**다. `ID18_19_20_21_22_23` 탭에는 여섯 콘텐츠 항목의 과거 판정과 근거가 들어 있다.
- **Coolblue 예시를 직접 확인했다:** https://www.coolblue.nl/koelkasten/lg . 2026-09-25 Codex 브라우저에서 LG 냉장고 소개, 큰 냉장고 이미지, 제품군별 이동 카드, 추천 제품, DoorCooling 등 기술 설명을 확인했다. 처음에는 쿠키 창이 뒤늦게 표시됐으며 개인화 선택을 켜지 않고 `Zelf instellen` 버튼을 누르자 창이 닫혔다. 이 한 번의 확인은 Zyte에서 같은 동작이 성공한다는 검증이나 9개 항목의 최종 판정이 아니다.
- **MediaMarkt 후보의 한계:** 앞선 선정 이유는 원본·CSV·동료 설정에 URL이 공통으로 있었기 때문이며 배너를 직접 확인했기 때문이 아니다. 2026-09-25 Codex 브라우저에서는 점검 안내 화면이 나와 본문을 확인하지 못했다. 사용자는 히어로 배너가 보이지 않는다고 보고했다. 화면 설명용 예시는 위 Coolblue를 사용한다. 배너 부재만으로 BCP가 아니라고 판단하거나, 점검 안내 화면을 항목 불충족으로 처리하지 않는다.
- 앞선 “담당자 확인 세 가지”는 예시 URL 세 개가 아니라 **평가 대상, 콘텐츠 합격 기준, 경계 사례 처리**라는 질문 묶음이다. 페이지 구조·클릭 동작처럼 직접 검증 가능한 문제는 먼저 조사하고, 업무상 판정 정책만 담당자에게 확인한다.

## 무엇을 판정하는가

크롤링은 페이지의 HTML·화면·링크 등 근거를 수집하는 일이다. 판정은 그 근거가 진단 항목의 조건을 충족하는지 판단하는 일이다. 집계는 여러 대상의 판정으로 비중 등을 계산하는 별도 단계다.

BCP 전체를 LG.com과 대조하는 규칙은 확인되지 않았다. 명시적 닷컴 USP 반영률은 PDP ID45다(S04 `Clinic 진단 항목!L36,T36,W36`). BCP ID20에는 핵심 USP 기준자료가 필요하며, T26은 모델별 USP 자료 확보 후 블록 지정을 요구한다. 이 기준자료의 공급자와 승인 버전은 별도 확인해야 한다.

## 권장 실행 순서

1. **작은 대상 목록을 만든다.** 처음에는 LG·리테일러 1곳·BCP 1개로 시작하는 것을 제안한다. 국가·언어·제품군·URL·대상 인정 근거를 기록한다. S04 `BCP!I11`의 MediaMarkt ES 냉장고 URL은 CSV와 S09 프로필에도 있어 첫 후보로 삼을 수 있다. 현재 접속은 미확인이며 해당 프로필 메모에도 새 수집 필요가 적혀 있다. URL: https://www.mediamarkt.es/es/brand/lg-electronics/frigorificos
2. **9개 항목의 검수 기준을 작성한다.** 원문 조건, O/N 예시, 판단 불가 조건을 나눈다. ID8 이미지 크기·빈 Alt, ID19/20의 경계, ID21/22 링크 검사 범위, 대상 BCP 인정 조건이 우선 확인 사항이다. S04 X17/X24/X25에는 다른 항목의 영문 문구가 섞여 있어 자동으로 규칙에 합치지 않는다.
3. **Zyte로 진단 근거를 수집한다.** 해당 리테일러의 BCP 프로필을 출발점으로 쿠키·지역 창, 스크롤·지연 로딩, 더보기·FAQ 펼치기를 점검한다. HTML, 구조화한 수집 상태, 보조용 전체 화면 이미지, 액션 로그, 최종 URL·시간·국가·브라우저 화면 크기를 보관한다. 링크 검증 전 BCP 상태를 저장한다. Hero Banner·Why LG·USP처럼 시각 확인이 필요한 후보는 전체 화면 이미지 대신 해당 요소의 위치·크기·표시 여부와 필요한 경우 요소 화면 이미지를 남긴다. 브라우저 DOM·스크린샷·액션 지원은 [Zyte 공식 문서](https://docs.zyte.com/zyte-api/usage/browser.html)에서 확인했다.
4. **수집 성공을 확인한다.** 차단 화면·다른 페이지로의 이동·로딩 미완료가 없는지 확인한다. FAQ가 없는 정상 페이지도 있으므로 FAQ 존재를 수집 성공 조건으로 강제하지 않는다. 실패·미수집을 항목 N으로 바꾸지 않는다.
5. **항목별로 판정한다.** ID9·10과 ID8의 기초 추출은 규칙 기반으로 시작할 수 있다. ID18·19·20·23의 콘텐츠 성격은 사람 검수와 LLM/비전 등의 자동화 후보를 비교한다. 텍스트는 DOM을 우선 활용하고 이미지 속 글자·시각 구조가 필요한 경우 OCR/비전을 검토한다. ID21·22는 상호작용과 도착 페이지 근거를 추가한다. OCR 또는 Jev를 모든 항목의 필수 단계로 확정하지 않는다.
6. **같은 수집본으로 수기 검수한다.** 과거 결과는 사례로 활용하고, 이번 수집 시점의 페이지를 검수한 결과와 비교한다. 수집 실패와 오판정을 분리하고 ID별 일치/불일치·근거 부족·처리 시간·비용을 기록한다. 1개 페이지 성공 후 다른 제품군과 사이트 구조로 확장한다.

ID21·22의 링크 목적지 확인은 BCP 기능 검증을 위한 최소 확인이며 PDP 전체 항목 진단으로 확장할 필요는 없다. 모든 링크 검사인지 표본 검사인지 먼저 정하고, 일부만 검사한 결과를 전체 정상으로 표현하지 않는다.

D026에 따라 [별도 시험 코드](../1차%20테스트/bcp-zyte-poc/scripts/run_jev_id18_trial.py)로 Elgiganten Brand Category Page 150~158행의 새 Zyte 수집본 9개를 Jev에 실제 전송했다. 요청에는 `capture-state.json`의 스크롤 전후 화면 기록에서 추린 위치·크기·이미지/영상 종류·주변 제목/문구와 페이지 제목·제품군을 넣었다. 스크린샷 파일은 보내지 않았다. 기존 ID18 값이나 직전 AI 화면 재검토 값도 요청에 넣지 않았다. 질문은 상단의 브랜드·제품군 대표 시각 자료를 Y, 상품 카드·카테고리 타일·기술 기능 설명 블록만 보이는 경우를 N, 영상만 대표 영역 후보이면 영상 인정 기준이 미정이므로 REVIEW로 구분하도록 했다. 이 질문 구성은 시험 조건이며 영상·상단 경계의 확정 기준이 아니다.
