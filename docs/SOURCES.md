[OSM_수집URL_진단대상35개_제품군필터_20261012.xlsx](../outputs/osm-target-filter-20261012-01a12f10/OSM_수집URL_진단대상35개_제품군필터_20261012.xlsx)은 위 474행 필터본의 `수집 URL` 목록을 제품군으로 다시 제한한 파일이다. 냉장고 44행, 세탁기·세탁건조기 67행, 건조기 32행, 스페인 ECI·MediaMarkt 식기세척기 각 1행, 합계 145행이다. 스타일러와 나머지 카테고리 329행을 제외한다. 원본 OSM 파일과 474행 필터본은 보존한다.

### 행 보존 수정본 — D036

[26년 OSM 대상 유통 리스트_260909_WIP_2026년 업데이트_수집url_수정본.xlsx](<../outputs/osm-history-20261013-01a12f10/26년 OSM 대상 유통 리스트_260909_WIP_2026년 업데이트_수집url_수정본.xlsx>)은 2026-10-13에 작성하고 D037로 열을 간소화한 이력 관리 파일이다. 원본의 18개 시트와 `수집 URL`의 1,489개 URL 행을 모두 보존했다. 국가·리테일러·URL은 A:C에 그대로 두고 D:F에 카테고리 코드·제외 여부·제외 사유를 추가했다. 원래 D:L의 내용은 G:O에 보존했다. 기존 URL 내용·순서·셀 서식을 대조했고 다른 17개 시트, 링크·피벗·외부 참조의 파일 구성 내용은 그대로 보존했다.

수집 대상 145행은 `제외 여부=N`, 나머지 1,344행은 `Y`로 표시했다. Y는 제외, N은 수집 대상이며 대상 리테일러 미해당과 제품군 비대상 등 사유를 구분한다. 최초 D036 작성본에는 OSM 원본 포함 여부·URL 행 수·메모 및 카테고리 명칭·세부 구분·확인 상태·근거 열도 있었으나 D037에서 사용자의 지시로 삭제했다. 원본에 없는 12개 대상 조합과 분류 근거는 아래 JSON의 최초 작성 기록에서 확인할 수 있다. 없는 URL 행을 임의로 추가하지 않았다. 카테고리를 확정하지 못한 114행은 `UNKNOWN`으로 남겼다. 새 코드와 배치는 이번 파일의 구현 선택이다.

분류 출처는 위 OSM 원본의 `수집 URL(과거)`, 각 URL의 제품명·검색어, 기존 제품군 필터의 행별 근거, 추가 페이지 제목·외부 분류자료다. [행별 근거 JSON](<../outputs/osm-history-20261013-01a12f10/26년 OSM 대상 유통 리스트_260909_WIP_2026년 업데이트_수집url_수정본_행별근거.json>)에는 원본 해시·원본 행 번호·선정 여부·분류 근거·참고표 대응을 저장했다. 원본 파일은 변경하지 않았다.

2026-10-13 표시 오류 보정: 최초 열 이동에서는 `수집 URL` 시트의 피벗 표 표시 위치가 원본 G:H에 남아 Excel의 접기·펼치기 버튼과 경계선이 두 노란색 열에 잘못 표시됐다. 현재 파일은 피벗 표시 위치를 오른쪽 `INSTANCE / ONLINE_STORE` 표의 `J2:K40`으로 수정했다. 피벗 원본 데이터 범위 `A1:C1490`, URL 내용·선정 여부·다른 시트는 유지했다. 배포한 파일과 동일한 검증용 복사본을 실제 Excel에서 열어 G:H의 2~40행이 비어 있고 접기·펼치기 버튼이 J열의 국가 항목에 표시되는 것을 확인했다. 위의 “피벗 보존”은 원본 데이터·필드·기능 보존을 뜻하며 표시 위치 설정은 이동한 셀에 맞춰 보정했다.

PPT에 `Manual/Crawling`, `Daily/Monthly`, `Y/N`이 모두 추출돼 있으면 색상이나 선택 표식이 빠졌을 수 있다. 텍스트 나열만으로 선택값을 추정하지 말고 Excel 정의 또는 원본 화면을 확인한다.

Excel의 날짜 셀은 표시 서식 없이 일련번호로 나올 수 있고 백분율은 0–1의 저장값으로 나올 수 있다. 셀의 저장값과 표시값을 구분한다. 공유 수식은 원본 수식과 셀 위치를 이용해 상대 참조를 복원했으며 OOXML 속성을 함께 기록했다. 빈 셀을 임의로 채우거나 병합 셀 값을 복제하지 않았다.

일부 Excel 시트는 실제 값보다 훨씬 큰 사용 범위를 선언한다. 예를 들어 S05 `Improvement Task`의 최대 행 선언은 데이터 건수가 아니다. 추출기는 실제 값·수식이 있는 셀을 기준으로 처리한다.

이번 작업은 원본을 로컬에서 읽었다. CSV 안의 외부 저장소 URL에 접속하거나 원본을 외부 서비스에 업로드하지 않았다.

## 갱신 방법

추출기는 [scripts/extract_context.py](../scripts/extract_context.py)다. Python 3과 `python-docx`, `python-pptx`, `openpyxl`을 사용하며, 원본을 수정하지 않고 추출본·카탈로그·manifest를 다시 쓴다.

```bash
python3 scripts/extract_context.py
```

현재 Codex 환경에서 확인한 Python 경로는 `/Users/codestepseunghee/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3`다. 다른 환경에서는 위 패키지가 설치된 런타임을 사용한다. 산출물 폴더를 먼저 삭제할 필요가 없다.

1. 새 버전 원본을 보존하고 출처·적용 상태를 확인한다. 같은 접두사의 원본이 둘 이상이면 추출기의 `SOURCES` 매핑을 수정해 대상 파일을 명시한다. 추출기는 임의로 최신 파일을 선택하지 않는다.
2. 추출기를 실행하고 원본 해시·지표 ID·시트 수·주요 셀을 확인한다.
3. 변경된 정의와 기존 계산의 차이를 BUSINESS_RULES.md에 반영한다. 자동 추출만으로 마스터의 의미가 갱신되지는 않는다.
4. 사용자 확정 내용은 DECISIONS.md에 남기고 PROJECT_CONTEXT.md의 상태·날짜를 갱신한다.

기계 추출본에 직접 해석을 덧쓰면 재실행 시 사라진다. 해석은 PROJECT_CONTEXT.md / BUSINESS_RULES.md / DECISIONS.md에 기록한다.
