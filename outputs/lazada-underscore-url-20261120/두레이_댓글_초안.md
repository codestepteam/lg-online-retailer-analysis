# Lazada `___{compress->…}` 주소 건 후속 댓글 초안 (2026-11-23)

추가로 확인해 보니, 이 쌍은 10월 OSM 추출 쿼리에서 걸렀어야 하는 중복이었습니다.

## 원인

- 10월 OSM 추출 쿼리는 주소에서 `?` 뒤 꼬리표를 지운 뒤, 같은 주소를 한 행으로 묶습니다.
- 그런데 Lazada의 `___{compress->…}`는 `?` 없이 주소 끝(`.html` 바로 뒤)에 붙어 있습니다.
- 그래서 쿼리가 원래 주소와 `___{compress->…}` 주소를 서로 다른 주소로 보고 두 행을 모두 뽑았습니다.
- 두 주소는 같은 상품 번호(예: `i3247984667`)이고, 직접 열어 보면 같은 PDP가 뜹니다.

## 처리 방향

- 같은 상품이므로 두 행 모두 포함인 99쌍(싱가포르 43, 태국 56, 이 중 LG 35쌍)은 원래 주소 행만 남기고, `___{compress->…}` 주소 99행은 중복으로 제외하겠습니다. 포함 수가 99행 줄어듭니다.
- 두 행 모두 제외인 163쌍은 판정이 바뀌지 않습니다.
- 이 행들은 10월 30일 중복 정리 때 외부 판매자로 제외 상태여서 비교 대상에 들지 않았습니다. 10월 31일 브랜드 공식점 포함(E4) 반영으로 다시 들어왔을 때는 주소가 글자 그대로 같은지만 확인해서 걸리지 않았습니다.
- 11월부터는 추출 쿼리에서 `___` 뒤를 지운 주소로 묶도록 고쳐, 같은 상품이 두 번 뽑히지 않게 하겠습니다.
