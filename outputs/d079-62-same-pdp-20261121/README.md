# Costco, Falabella "주소 글자만 다른" 62쌍 124행 상품 상세 페이지(PDP) 대조

2026-11-21 작업. v8.1에서 "주소의 상품 번호 같음"으로 중복제거된 62행과 그 대표 행 62행을 사이트에서 다시 수집해, 62쌍이 각각 같은 PDP인지 판별했다. 판정 CSV, docs/DECISIONS.md, READ.md는 고치지 않았다. 커밋, 푸시, 두레이 등록도 하지 않았다.

## 엑셀 정리 (11-21, 사용자 요청)

## 두 번째 수집: 전체 페이지 그림 (11-21, 사용자 요청)

첫 수집의 그림은 화면 한 장(1200x800)뿐이었고 Falabella는 오른쪽이 잘려 있었다. 사용자가 "완벽한 근거"를 요청해 124행을 다시 수집했다. **지금 엑셀, values.csv, 판정은 모두 이 두 번째 수집(작업 이름 `f-`)을 쓴다.** 첫 수집본(`m-`)은 지우지 않고 다른 도구 재확인 자료로 남겼다.

- 도구: 두 리테일러 모두 이 맥의 Chrome을 임시 프로필의 별도 창으로 띄워 수집했다. 유료 호출은 없다.
  - Costco: 화면 1200x800, 한국 접속(VPN 끔), 창 3개 병렬(쌍은 같은 창에서 연달아), 86행 모두 응답 200.
  - Falabella: 화면 1440x900, 칠레 VPN, 창 1개로 주소 사이 약 30초 간격, 38행 모두 응답 200. 보안 확인 화면이 2번(행 8642, 8911) 떠서 사용자가 직접 푼 뒤 그 주소부터 이어 갔다. 나는 풀지 않았다. VPN을 끄거나 빠르게 열면 Falabella는 403 차단 또는 보안 확인이 나왔다.
- 그림: 값을 읽은 것과 같은 접속에서, 화면을 한 칸씩 실제로 내리며 그 칸의 사진이 다 뜬 뒤 찍어 이었다(`collect_chrome.mjs`의 FULL=1, `stitch_full.py`). 화면을 따라다니는 영역은 제자리에 한 번만 찍히게 했다. `screenshots/f-<행번호>.jpg`가 전체 페이지(Costco 폭 1200, Falabella 폭 1440), `f-<행번호>.top.jpg`가 화면 한 장, `f-<행번호>.full.json`이 높이와 조각 기록이다.
- Falabella 수집 보완: 닫혀 있던 "Especificaciones (사양)" 영역을 열고 "Mostrar más (더 보기)"를 한 번만 누르게 했다(첫 수집에서는 같은 단추를 겹쳐 눌러 다시 접혔다). 제조사 설명 문서는 Chrome 안에서는 페이지에 그대로 그려져 그림에 보인다. 글과 그림 경로 값은 첫 수집 때 같은 문서 주소 5개를 따로 열어 저장한 `raw/frames/`에서 읽었다(문서 주소는 두 번째 수집에서도 같은 5개).
- 결과: 같음 60, 다름 0, 확인 못 함 2. 첫 수집과 같다. 10, 11, 13 때문에 다시 수집한 쌍은 없다.
- 그림 점검: 그림 높이가 수집 때 잰 페이지 높이와 같음(124장), 글자 인식으로 상품명 120/120과 가격 117/120(나머지 3장은 상품 번호로 통과), 안내 화면 4/4. 124장의 윗부분을 모음 그림 11장으로 직접 봤다. 수집 기록에 "화면에 보이는데 끝내 안 뜬 사진"이 그림당 0~1개 있었고, 표본 3장(행 8281, 8616, 8668)을 전체로 봤을 때 빈 곳은 없었다. 어떤 사진인지는 특정하지 못했다.
- 다른 도구 재확인(검증 5): 미리 뽑은 10쌍 모두 본 판정과 같다. Costco 8쌍은 앱 내장 브라우저 수집본(`b-`), Falabella 2쌍(51, 61)은 첫 수집의 Zyte 수집본(`m-`)으로 다시 판정했다. 첫 수집 때 "Falabella 2쌍은 재확인 못 함"이던 한계는 풀렸다.
- 엑셀 크기: 약 57 MB. 전체 페이지 그림을 폭 800으로 줄여 2000픽셀 높이 조각으로 넣었다(조각 594개).
- 아래 절들은 첫 수집 때의 기록이다. 도구 표, 호출 건수, 실패 목록은 첫 수집 기준으로 읽는다.

## 고른 도구와 이유

| 리테일러 | 본 수집 도구 | 이유 |

## 실행한 명령 (이 폴더에서)

```sh
PY=~/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
$PY make_jobs.py                                    # 대상 124행, 대조군, 실험 주소 고르기 → jobs.json
node collect_chrome.mjs <임시 프로필> costco_chrome_queue.txt   # Costco 104건(본 86, 반복 6, 대조군 6, 실험 6)
$PY zyte_falabella_pilot.py --run                   # Falabella 유료 시험 12회
xargs $PY zyte_falabella.py --run < zyte_falabella_queue.txt    # Falabella 50회
$PY zyte_falabella.py --run o2-8616 s2-8616         # 실험 재수집 2회
node collect_frames.mjs <임시 프로필> frame_srcs.json           # Falabella 제조사 설명 문서 5개
$PY extract_values.py                               # raw → extracted (항목 1~15 값)
$PY make_all.py --excel                             # 판정, values.csv, 엑셀, 두레이 초안
$PY crosscheck.py                                   # 다른 도구 재확인, 반복 수집 비교 → crosscheck.json
swiftc -O ocr.swift -o <ocr>; $PY verify.py <ocr>   # 검증
```

앱 내장 브라우저 수집(재확인용 `b-` 71건)은 `receive_pages.py`(로컬 수신기)와 `collector.js`로 했다. `collector.js`는 두 브라우저에서 같은 것을 쓴다. Zyte 안에서는 같은 절차를 줄인 `zyte_page_script.js`를 실행했다.
