# 02. 목표 구조: 월간 PDP 모수 자동화 파이프라인

작성일: 2026-11-06. 전제: [01 진단](01_10월_과정_진단.md)이 맞다. 규칙 값은 [03 명세](03_규칙_설정_명세.md)에 있다. 이 문서는 **어떤 단계가 무엇을 받아 무엇을 내놓는지**와 **사람이 끼어드는 지점**을 정한다.

## 1. 한 줄 요약

매달 한 번, `EY 엑셀 + OSM(BigQuery) + 사이트 검색` → 설정 파일로 거르기 → Zyte(유료 수집 API)로 페이지 확인 → 판매자·중복 판정 → **26열 전체판정 CSV(v1)** 를 만든다. 사람은 유료 호출 승인, 막힌 사이트의 수동 수집, "확인 필요" 행 검토, EY 피드백 반영 결정만 한다.

## 3. 폴더 배치 (후보, 이름은 07에서 확정)

```
pdp 모수 자동화/
  README.md, 01_…md ~ 07_…md          ← 계획 문서(이 세션)
  pipeline/                           ← Opus가 만들 코드
    s0_config.py  s1a_osm.py  s1b_search.py  s2_filter.py
    s3_pages.py   s4_sellers.py  s5_judge.py  s6_share.py
    rules/        ← 리테일러별 판매자·상태 추출 함수(설정표에서 호출)
    tests/        ← 규칙 테스트·10월 입력 대조
  runs/
    2026-11/
      config/  candidates/  html/  judgments/  final/  changes/  logs/
```

- `runs/{YYYY-MM}/`가 **한 회차**다. 모든 단계는 이 폴더만 읽고 쓴다.
- 10월 자료(`pdp 모수 추출/`)는 **읽기 전용 비교 자료**다(10월 입력으로 11월 코드를 돌려 v5와 대조). 옮기거나 고치지 않는다.
- 저장소 루트 `.env`의 `ZYTE_API_KEY`와 `~/.config/lgops/key`는 그대로 쓴다. 키 값은 어떤 파일·로그에도 적지 않는다.

## 4. 가로지르는 원칙

1. **이어받기**: 모든 단계는 출력이 이미 있으면 건너뛴다(`zyte_run.py`의 완료 건 건너뛰기 패턴 유지). 중간에 끊겨도 같은 명령으로 재개.
2. **유료·외부 호출은 기본 미리보기**: S1a·S1b·S3는 `--dry-run`이 기본. 건수·예상 비용·대상 리테일러를 출력하고, 사용자가 "진행"이라고 한 뒤 `--run`. (글로벌 규칙 "유료 수집 호출: 호출 건수와 예상 비용")
3. **행은 지우지 않는다**(D036). 제외도 단계·사유·메모와 함께 남긴다.
4. **설정과 코드 분리**: 03 문서의 모든 값은 `config/`에서 읽는다. 다음 달에 EY 엑셀만 바뀌면 코드 수정 없이 S0만 다시 돌린다.
5. **정정은 한 방식**: 11월 결과 v1에 대한 사용자·EY 피드백은 "변경 대상 CSV"(26열 + `변경요청_모수 포함 여부`·`확인상태` 등 추가 열, `make_v5.py` 입력 형식)로 받아 다음 버전 생성기가 적용한다. 기존 CSV는 절대 고치지 않는다(D085).
6. **10월 상태와 현재 화면 구분**: 판정 근거에는 확인 시점을 적는다(`make_v5.py` 메모 패턴 "… 당시 판매자는 별도 확인하지 않음").
7. **외국어 문구 괄호 뜻**(D102): 제외사유·메모에 외국어 문구를 쓰면 괄호 뜻을 붙인다.

## 5. OSM 실행 경로 (읽기 전용으로 확인한 사실)

- 콘솔 `https://lg-hs-console.codestep.co.kr/`의 04 "PDP URL 모수" 쿼리는 로컬 `uv tool` 설치본과 같은 코드다: `lgops` 명령, 패키지 `~/.local/share/uv/tools/lg-bq-console/lib/python3.12/site-packages/bqconsole/`.
- SQL 생성: `from bqconsole.pdp import render_pdp` → `render_pdp(params, countries, FIXED_TARGETS['targets'], COUNTRY_CODES)`. `@target_date`는 `DATE 'YYYY-MM-DD'`로 치환돼 들어간다. 20,000자 초과면 `ValueError`.
- 실행: `lgops --out runs/2026-11/candidates/osm_audit.jsonl bq @runs/2026-11/candidates/osm_query.sql`. `--dry-run`을 붙이면 처리량만. `--out`을 쓰면 행 수 제한이 없다(`--max-rows` 기본 10,000은 `--out` 없을 때만).
- 승인 테이블에 L1 `TRPURC_OSM_PRODUCT_DAILY_L`이 포함돼 있다(`policy.py TABLES` 확인). 사람 로그인은 필요 없다(키 파일 `~/.config/lgops/key`).
- **권고(AI 제안)**: `pdp_view='audit'`, `pdp_filter_mode=False`로 원천 모수 전체 행과 판정 플래그(MARKETPLACE·OUT_OF_STOCK·USED_PRODUCT·OUTLET·PAGE_NOT_FOUND, SLLR_NAME·INV_STAT_INFO·AVLBL_STAT)를 받고, 제외는 S2~S5에서 EY 규칙으로 판정한다. 콘솔 플래그는 `메모`에 보조 근거로 남긴다. 이유: 콘솔 `fixed-targets.json`의 브랜드가 EY 시트와 다른 곳이 많아(03 문서 2장 P-D) 콘솔 필터를 그대로 믿을 수 없다.
- 예비 경로: 콘솔 `/api/v1/action`(submit→status→page, 별도 `QUERY_API_KEY`). 1번이 되면 쓰지 않는다. 둘 다 안 되면 사용자가 매달 콘솔에서 04를 돌려 결과를 전달한다(사용자 결정 2026-11-06).

## 6. 산출물 계약

- **26열 이름·순서·값은 v5와 완전히 같다**(03 문서 9장). 열을 더하지 않는다(D093 전례). 단, 11월부터 기본인 xlsx 공유본은 이름과 값은 같고 열 자리만 `share_columns_xlsx` 순서로 바꾼다(D163). 예전 순서가 필요하면 `s6 --format csv`.
- 공유용 v1 외에 `final/summary.csv`(리테일러·제외단계별 건수)와 `final/vs_prev_month.md`(전월 포함 행 대비 새로 포함·빠진 URL 수)를 함께 낸다. 두 파일은 내부용이며 EY에 보내지 않는다.
- `final/verify.json`에 행 수·열 수·제외단계 분포·해시를 적는다(`outputs/pdp-version-comparison-20261030-a5cabba9/verify.py` 패턴).

## 7. 검증: 10월 입력으로 v5와 비교

11월 코드에 10월 입력을 그대로 넣어 v5 최종 판정과 같은지 본다(01 문서 5장). 10월의 v1→v5 정정 과정을 되풀이하는 것이 아니라 결과만 맞춘다. 2026-11-06 새 규칙(Alza 세 단어·BOSCH HAUSGERÄTE·판정 순서)으로 달라지는 행은 의도된 차이로 기록한다.

| 대상 | 입력 | 비교 상대 | 통과 기준 |
| --- | --- | --- | --- |
| S2 | 10월 OSM CSV 3개 + `상품카드.csv` | v5의 `①브랜드`·`②제품군`·`③리리부`(단어·URL 규칙분) 판정 | 차이 행마다 사유 기록. 사유 없는 차이 0 |
| S3·S4 | 11월 재확인 HTML(DIENMAYXANH 453, eXtra 272, 독일 MediaMarkt 195) | 각 폴더의 변경 대상 CSV | 일치 100% |
| S4 Sharaf | `sharaf-157-20261105`의 25건 판정표 | 외부판매자 9건 | 일치 100%(HTML은 없으므로 저장된 판정표·근거 문구로 표본 테스트) |

| S6 | v5 내부판→공유용 변환 | v5 공유용 | 열·값 완전 일치 |

## 8. 사람이 남는 지점 (06 문서에서 절차로 풀어 씀)

1. S1a·S1b·S3 유료 호출 승인.
2. S1b에서 Zyte가 막힌 리테일러의 수동 수집(같은 CSV 계약).
3. S5 결과의 `확인 필요` 행 검토.
4. EY 피드백을 변경 대상 CSV로 옮기는 판단.
5. S0 `config_diff.md` 검토(검색어·브랜드가 바뀌었을 때 의도된 변경인지).
