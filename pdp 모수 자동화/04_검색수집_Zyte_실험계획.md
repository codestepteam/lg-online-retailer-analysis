# 04. OSM 미보유 12곳 검색 수집: Zyte 브라우저 실험 계획

작성일: 2026-11-06. 사용자 결정: "Zyte 브라우저로 자동화 시도, 안 되는 곳만 수동". 이 문서는 **실험 설계**다. 실제 호출은 Opus 단계에서 건수·비용을 보여 주고 사용자 "진행" 뒤에만 한다.

Zyte = 유료 수집 API(`https://api.zyte.com/v1/extract`, Basic Auth, 키는 저장소 루트 `.env`의 `ZYTE_API_KEY`). 두 방식: `httpResponseBody`(HTML만 받음, 싸고 빠름) / `browserHtml`(브라우저가 렌더링한 뒤 받음, 비싸고 느림, `actions`로 클릭·스크롤 가능, 액션 총 60초 제한). 국가 지정은 `geolocation` 파라미터.

## 3. 실험 설계 (WP1-1, 유료 — 미리보기 후 승인)

### 3-1. 리테일러별 1차 탐색 (각 1~3요청, 총 ≤ 36요청)

각 리테일러의 **검색어 1개, 1페이지**를 세 방식으로 받아 본다.

| 방식 | 요청 | 판정 |
| --- | --- | --- |
| H | `httpResponseBody` + `geolocation` | 카드가 HTML에 들어 있으면(서버 렌더링) 최저가 방식 채택 |
| B0 | `browserHtml` + `geolocation`, 액션 없음 | 카드가 렌더링 뒤에 생기면 채택 |
| B1 | `browserHtml` + `scrollBottom` 반복 또는 "더 보기" 클릭 액션 | 무한 스크롤·버튼 로딩 사이트 |

판정 기준: 받은 HTML에서 (1) 카드 수가 10월 `상품카드.csv` 같은 검색어 1페이지 카드 수와 같고, (2) 표시 전체 수(예: "847 results")를 읽을 수 있고, (3) 광고 표식이 보이고, (4) 차단 정규식(`page_check.py` BLOCK)에 안 걸리면 **성공**.

### 3-2. 페이지 넘김 방식 결정

| 유형 | 방법 | 해당 가능 리테일러(10월 기록 기준, 확인 필요) |
| --- | --- | --- |
| 페이지 번호 URL | `?page=N` 식으로 요청을 나눔. 60초 제한 영향 없음. **기본** | Datart, Alza, Media Expert, RTV EURO AGD, Worten(21페이지 다음 버튼 비활성 사례), Cairo Sales, Electroplanet, Falabella, Sharaf DG |
| "더 보기" 버튼 | 브라우저 액션으로 클릭 반복. 60초 안에 몇 번 되는지 측정 → 넘으면 페이지 URL 파라미터 탐색 | 헝가리 MediaMarkt(30회차 뒤 버튼 사라짐) |
| 무한 스크롤 | `scrollBottom` 반복 | Appliance Online(확인 필요) |

### 3-3. 상한과 종료

- 검색어별 **상위 1,000카드**(D056). 표시 전체 수가 1,000 미만이면 끝 페이지까지.
- 종료 신호: 카드 0개 페이지, "검색 결과 없음" 문구(헝가리 `Nincs találat!`), 다음 버튼 비활성, 마지막 페이지 번호 반복.
- 10월처럼 `검색어별_건수대조.csv`와 같은 27열 대조표를 만든다. 표시 수와 수집 수가 다르면 `완료구분`에 적고 **재수집하지 않는다**(D060 전례; 재수집 여부는 사람이 결정).

### 3-4. 성공 기준 (리테일러별 자동/수동 분류)

| 결과 | 분류 |
| --- | --- |
| 10월 같은 검색어의 표시 전체 수 ±10% 안, 카드 수 일치, 광고 표식 일치, 차단 없음 | **자동** |
| 수집은 되지만 광고 표식·표시 전체 수를 못 읽음 | 자동(결함 기록) + 사람 표본 확인 |
| 지역 차단·CAPTCHA·520/403 지속(3회 재시도 후) | **수동**(10월 방식 유지, 같은 CSV 계약으로 넣음) |

### 3-5. 비용 추정 (단가는 2장 B에서 채움)

| 항목 | 요청 수 | 비고 |
| --- | --- | --- |
| 1차 탐색 | ≤ 36 | 12곳 × 3방식 |
| 본 수집(전부 자동 성공 가정) | ≈ 1,843 브라우저 요청(10월 페이지 수) + 재시도 10% ≈ 2,030 | HTML 방식이 되는 곳은 그만큼 저렴 |
| PDP 확인(S3, 참고) | 10월 1차 거르기 통과 행 수(Opus가 `step1_집계.csv`에서 확인) × 1 HTML + 실패분 브라우저 | 검색 수집과 별도 |

단가 미확인이므로 금액은 적지 않는다. Opus는 `--dry-run` 출력에 "요청 수 × 단가 = 예상 비용"을 찍고 승인 뒤 실행한다.

## 5. 실패 시 수동 대체 경로

- 10월과 같은 방식(국가 VPN + 내부 브라우저 + 함수기록 JS)으로 수집하고 **같은 14열 `search_cards.csv`** 로 `candidates/`에 넣는다. 이후 단계는 자동·수동을 구분하지 않는다.
- `search_reconcile.csv`의 `접속근거` 열에 `Zyte geolocation=XX` 또는 `수동 VPN XX`를 적어 출처를 남긴다.
